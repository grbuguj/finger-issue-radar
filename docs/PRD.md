## 1. 배경

핑거는 금융사 비대면 채널 구축, 전자금융·간편결제(NextPay), 디지털자산·기후탄소(미래사업), AI 사업, 공공 사업(Nexus GovOps), BPO까지 사업 영역이 넓습니다. 그만큼 매일 확인해야 할 외부 이슈가 많습니다.

- 2026년 7월 금융위원회가 금융권 내부 업무의 생성형 AI 활용을 허용하는 등 **규제 변화 속도가 빨라졌습니다.**
- 2026년 10월 조직개편으로 FV·DX·AX·DA·Tech 그룹, 11개 본부 체계가 되면서 **"이 이슈는 어느 본부 소관인가"를 판단하기가 더 어려워졌습니다.**
- 1회차 교육 후기에서 지적된 다음 과제는 **"만든 도구 안에 AI의 판단 단계를 넣는 것"**이었습니다. 이 서비스는 AI가 분석 초안을 만들고 사람이 판정하는 구조를 처음부터 설계에 넣었습니다.

## 2. 문제 정의

| # | 문제 | 지금의 방식 | 결과 |
|---|---|---|---|
| P1 | 출처가 흩어져 있다 | 금융위·금감원 보도자료, 국회, 국가법령정보센터, 전자공시, 국내 뉴스, 해외 매체를 따로 확인 | 놓치는 이슈가 생김 |
| P2 | 같은 이슈도 본부마다 의미가 다르다 | 각자 기사를 읽고 각자 해석 | 예) "망분리 예외 완화" = AI사업본부에는 사업 기회, Tech 본부에는 보안성 평가 점검 과제 |
| P3 | 시행일을 놓친다 | 담당자 기억과 메모에 의존 | 시행 직전에야 대응 |
| P4 | 공유가 링크로 끝난다 | 메신저로 기사 링크 전달 | "우리 본부가 무엇을 해야 하는지, 누가 확인했는지"가 남지 않음 |

## 3. 목표와 비목표

### 목표 (Goals)
- G1. 본부 담당자가 **아침 5분 안에** 우리 본부 관련 이슈를 확인하고 판정을 끝낸다.
- G2. 이슈마다 **본부별 영향**과 **근거의 성격(원문 근거 / 가설)**을 함께 보여 준다.
- G3. 시행 30일 이내 법령을 **D-day로** 놓치지 않게 한다.
- G4. 판정 결과를 **메일에 바로 붙는 주간 브리핑**으로 공유한다.
- G5. AI는 정리까지만 하고, **액션 여부는 사람이 판정**한다.

### 비목표 (Non-goals, 현재 버전)
- 실제 데이터 수집과 AI 분석 연결 (현재 모든 데이터는 예시 목업)
- 판정 결과의 서버 저장과 본부 내 공유
- 로그인·권한 관리
- 이슈에 대한 자동 조치(메일 자동 발송 등)

## 4. 사용자

| 페르소나 | 상황 | 이 서비스에서 하는 일 |
|---|---|---|
| 본부 담당자 (기획·PM, 예: Nexus 본부 GovOps팀) | 매일 아침 외부 이슈 확인 담당 | 우리 본부 브리핑 확인 → 판정 → 주간 브리핑 복사 |
| 본부장·팀장 | 시간이 없음, 결론만 필요 | 액션 필요 목록, 시행 임박 법령, 판정 진행률만 확인 |
| 전사 (경영기획실·미래전략실) | 전사 흐름 파악 | 전사 공통 화면에서 중요도 상 이슈, 섹터별 분포, 이슈↔본부 관계도 확인 |

## 5. 사용자 시나리오

**S1. Nexus 본부 담당자의 아침 5분**
1. 사이트를 열면 **전사 공통** 화면이 뜬다. 중요도 상 이슈 수와 시행 임박 법령 수를 먼저 본다.
2. 본부 바에서 **Nexus 본부**를 누른다. 브리핑이 Nexus 관련도 순으로 다시 정렬되고, 관계도에서 Nexus와 연결된 이슈만 강조된다.
3. 섹터 보드에서 **공공**을 눌러 조달·공공금융 이슈만 추린다.
4. "공공 금융기관 차세대 시스템 발주 확대" 이슈의 우리 본부 영향(`원문 근거`)을 읽고 **액션 필요**로 판정한다.
5. `가설`로 표시된 이슈는 상세 패널에서 다른 본부 영향까지 비교한 뒤 **참고** 또는 **무관**으로 판정한다.
6. **주간 브리핑 복사**를 눌러 팀 메일에 붙여 넣는다.

**S2. 본부장이 30초 확인**
- 오른쪽 "우리 본부 판정" 링 차트로 판정 진행률을, 액션 필요 목록으로 할 일을, 법령 타임라인으로 다가오는 시행일을 본다.

## 7. 핵심 로직

### 7.1 관련도 (`relevance`)
```
전사 공통:  관련도 = 중요도 / 3
본부 선택:  관련도 = min(1, 키워드일치수 × 0.22 + (그 본부 영향이 있으면 0.5) + 중요도 × 0.06)
"관련 이슈" = 관련도 ≥ 0.4
```
- 키워드는 본부가 직접 고칠 수 있어, 정렬 기준을 사람이 조정할 수 있습니다.

### 7.2 근거 구분
| 값 | 표시 | 의미 | 판정자의 행동 |
|---|---|---|---|
| `f` | 원문 근거 | 원문에 그 본부 업무와 직접 이어지는 내용이 있음 | 내용 확인 후 판정 |
| `h` | 가설 | AI 추론 | **반드시 원문과 대조 후 판정** |

현재 데이터 기준 본부 영향 45건 중 23건(51%)이 `가설`입니다. AI만으로 액션 여부를 정하면 안 되는 이유이고, 판정 단계를 사람에게 둔 근거입니다.

### 7.3 판정 상태
- `verdicts[본부id][이슈id] = "act" | "ref" | "no"`
- 같은 버튼을 다시 누르면 판정 취소
- 판정 대기 = 그 본부 영향이 있는 이슈 중 판정이 없는 것

## 8. 데이터 모델

`index.html`의 데이터 영역(`/* 목업 데이터 */`)은 `issue-brief` Skill의 출력 형식과 같습니다.

```js
// 이슈
{ id, inst, cat, imp, h, title, sum: [3줄], kw: [2~6개], impacts: { 본부id: ["영향 한 문장", "f"|"h"] } }
// 법령
{ name, short, kind: "new"|"rev"|"pre"|"bill", eff: 시행까지 남은 일수|null, span, orgs: [본부id], note }
```

| 데이터 | 개수 | 설명 |
|---|---|---|
| `ISSUES` | 15 | 처음 표시되는 이슈 |
| `QUEUE` | 3 | 실시간 유입 연출용 이슈 |
| `LAWS` | 6 | 제정 1, 개정 3, 입법예고 1, 국회 계류 1 |
| `INST` | 11 | 발표 기관 → 섹터(정부·공공·민간) 매핑 |
| `CAT` | 7 | 규제, 은행, 핀테크, 디지털자산, AI, 보안, 공시 |
| `ORG` | 11 + 전사 | 2026.10 조직도 |
| `GLOBAL`, `BANKFEED` | 5, 5 | 피드 |

브라우저 저장(localStorage): `radar.verdicts`(판정), `radar.stars`(북마크), `radar.read`(읽음), `radar.kw`(관심 키워드). 모든 읽기·쓰기는 `try/catch`로 감싸 저장소가 막혀도 화면은 동작합니다.

## 9. AI 설계

### 9.1 AI가 하는 일과 사람이 하는 일
| 단계 | 담당 | 내용 |
|---|---|---|
| 수집 | 시스템 | 보도자료·법령·공시·뉴스 (다음 단계) |
| 분류·요약 | **AI** | 발표 기관, 분류, 중요도, 세 줄 요약, 키워드 |
| 본부 영향 초안 | **AI** | 본부별 영향 한 문장 + 근거 구분 |
| 규칙 검사 | **하네스** | Skill 규칙 위반 데이터는 화면에 올리지 않음 |
| 액션 판정 | **사람** | 액션 필요 / 참고 / 무관 |
| 공유 | 사람 | 주간 브리핑 |

### 9.2 Skill — `.claude/skills/issue-brief/SKILL.md`
원문 한 건을 위 데이터 형식으로 바꾸는 분석 규칙입니다.
1. 요약은 원문에 있는 사실만 (숫자·날짜·기관명 원문 그대로)
2. 본부 영향은 "무엇을 확인하거나 해야 하는지" 한 문장, 팀 이름이 있으면 사용
3. 근거 구분 `f` / `h` 필수
4. 영향 없는 본부는 억지로 넣지 않음
5. 중요도 기준(3: 시행일 확정 규제·제재·사고 / 2: 고객사·경쟁사·입법 논의 / 1: 참고)
6. **판정은 데이터에 넣지 않는다 — 사람이 한다**

### 9.3 하네스 — `scripts/check.mjs`
`index.html`의 데이터 영역을 Node `vm`으로 읽어 Skill 규칙 준수를 자동 점검합니다.

```bash
node scripts/check.mjs
# 이슈 18건 · 법령 6건 점검
# 본부 영향 45건 중 가설 23건 (51%) — 판정자 확인 대상
# ✓ 전체 297건 통과
```

| 검사 항목 | 대응 Skill 규칙 |
|---|---|
| 발표 기관·분류 코드가 정의돼 있는가 | 출력 형식 |
| 중요도가 1~3인가 | 규칙 5 |
| 제목 60자 이내, 요약 정확히 세 줄, 키워드 2~6개 | 출력 형식 |
| 영향 본부가 1개 이상이고 모두 실제 본부 id인가 | 규칙 2·4 |
| 근거 구분이 `f` 또는 `h`인가 | 규칙 3 |
| 영향 문장 80자 이내 | 규칙 2 |
| 데이터에 판정(`verdict`)이 없는가 | 규칙 6 |
| 법령 구분 코드, 관련 본부 id, 시행일 형식 | 출력 형식 |

실패하면 종료 코드 1을 반환하므로 CI나 배포 전 검사에 그대로 쓸 수 있습니다.

## 14. 현재 한계 (정직하게)
- **모든 기사·수치·법령·기관 발표는 예시(목업)**입니다. 화면 오른쪽 위에 `MOCK` 표시가 있습니다.
- 실제 수집·AI 분석은 아직 연결하지 않았습니다. 분석 규칙(Skill)과 검사(하네스)는 완성돼 있어 연결 시 그대로 씁니다.
- 판정·북마크·키워드는 브라우저에만 저장됩니다.
- 로그인·권한이 없습니다.
