# 이슈 분석 규칙

원문 한 건을 받아 아래 형식의 이슈 데이터 하나를 만든다.

## 출력 형식
```js
{
  inst: "fsc",            // 발표 기관: fsc 금융위, fss 금감원, nas 국회, pipc 개보위, msit 과기부, mois 행안부, pps 조달청, bok 한은, bank 은행권, comp 경쟁사, ind 업계
  cat: "reg",             // reg 규제, bank 은행, fin 핀테크, dig 디지털자산, ai AI, sec 보안, dis 공시
  imp: 3,                 // 중요도 1~3
  title: "…",             // 원문 제목을 60자 안으로
  sum: ["…", "…", "…"],   // 정확히 세 줄
  kw: ["…"],              // 본부 관심 키워드와 맞출 키워드 2~6개
  impacts: { 본부id: ["영향 한 문장", "f" | "h"] }
}
```

## 규칙
1. **요약은 원문에 있는 사실만** 쓴다. 숫자·날짜·기관명은 원문 그대로.
2. **본부 영향**은 해당 본부가 "무엇을 확인하거나 해야 하는지"를 한 문장으로 쓴다. 팀 이름이 있으면 쓴다 (예: "전자금융사업팀 — 약관 점검").
3. 영향 근거 구분
   - `"f"` 원문 근거: 원문에 그 본부 업무와 직접 이어지는 내용이 있다
   - `"h"` 가설: AI 추론이다. 판정자가 반드시 확인해야 한다
4. 영향이 없는 본부는 넣지 않는다. 억지로 채우지 않는다.
5. 중요도 기준
   - 3: 시행일이 정해진 규제·법령, 본부 사업에 직접 영향, 제재·사고
   - 2: 고객사·경쟁사 동향, 입법 논의, 시장 변화
   - 1: 참고성 동향
6. 판정(액션 필요 / 참고 / 무관)은 **사람이 한다.** 분석 결과에 판정을 넣지 않는다.
